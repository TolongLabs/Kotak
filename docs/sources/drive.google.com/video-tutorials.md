## Apache 2.0 licence tutorial A (direct)

**[0:00]** Hi everyone. In this quick tutorial, you'll learn how to add the Apache 2.0 licence to your GitHub repository. Open your repository on GitHub and click Add file. Then select Create new file. In the file name box, type `LICENSE` in all capital letters. GitHub recognises this name and shows a new button. Click Choose a license template.

**[0:27]** From the list on the left, select Apache License 2.0. You'll see a summary of what the licence allows, like commercial use, modification, distribution and patent use. When you're ready, click Review and submit. GitHub fills in the full licence text for you. Give it a quick look, then click Commit changes. Enter a clear commit message, such as "Add Apache License 2.0 to the project". Keep Commit directly to the main branch selected, then click Commit changes.

**[1:00]** And done! Your repository now has a licence file. Apache 2.0 also shows up in the About sidebar and as a tab next to the README. Click the licence file to see the full licence, with its permissions, limitations and conditions. That's all it takes to open source your project under Apache 2.0. See you at SDC Hackathon 2026.

## Apache 2.0 licence tutorial B (manual)

**[0:00]** Hi everyone. Here's another way to add the Apache 2.0 licence: create the file yourself in VS Code, then push it with Git. Here's our repository. There's no licence file yet, so let's open the project in VS Code. In the Explorer, click the new file icon at the root of your project, and name it `LICENSE` in capital letters with no file extension. Then press Enter.

**[0:27]** Now we need the official licence text. Open a new browser tab and search for Apache 2.0 license. Open the result from apache.org. On the Apache page, click the text version link. Select all the text with Command-A and copy it with Command-C. Back in VS Code, paste it into your licence file with Command-V and save with Command-S.

**[0:49]** Now open the terminal and stage the file with `git add`. Commit _(as heard: "Start")_ with a clear message like "Add Apache 2.0 license to project". Then push it to GitHub with `git push origin main`. Head back to your repository on GitHub and refresh the page. Your licence file is now there, and GitHub shows the Apache 2.0 licence in the About sidebar and next to the README. Click the licence file to view the full licence text. That's the manual way to add the Apache 2.0 licence to your project. See you at SDC Hackathon 2026.

## Orbyte account setup

Added on 21 October 2026 with the [Domain 2 Orbyte registration](/docs/sources/discord.com/announcements.md#domain-2-orbyte-registration) announcement. A narrated screen recording whose title card reads "Domain 2 · Optional", "Orbyte account setup for Domain 2 teams" and "Create a demo Orbyte account on the Alpha Red Solutions platform", with each step numbered in a caption. The email address and verification code it shows are left out.

**[0:00]** Hi, Domain 2 teams. Here's how to create an account on Orbyte, the business platform from Alpha Red Solutions. Before we start, an important note: creating an Orbyte account is not compulsory. It's only to help you understand the platform. If Alpha Red Solutions doesn't approve your account in time, the organising committee can't be held responsible for the delay. The Domain 2 guide doesn't depend on it. **[0:30]** Go to the Orbyte sign-up page. The link is on screen _(`orbyte-xyz.alphareds.com`)_. Enter your email and continue with email. On Register your organization, make sure Customize organization code is unticked. A unique code will be generated for you. For company name and company registration number, just use your team name. **[0:58]** Orbyte sends an 8-digit verification code to your email. Open the email and copy the code. Back on Orbyte, paste the code and click Verify email. Your email is verified, and your application is now pending approval. Alpha Red Solutions will review it and email you when a decision is made. You can sign in again any time to check. **[1:31]** That's it. Remember, the Orbyte account is optional and just for your understanding. Good luck, Domain 2 teams, and see you at SDC Hackathon 2026.

## Website text shown in the submission videos

Both submission videos show the website's preview pages, so the mentors, times and links in them are examples. The page text explains the rules.

### Mentor booking page

- **Before Orientation Day** (portal): "Mentoring opens after Orientation Day, once your domain has been assigned. Each team will book one session with a mentor. The mentors and their times will appear here once your domain is assigned."
- **Booking open** (portal): "Booking is open until 25 October 2026. Each team books one session — times are limited and first come, first served, so we recommend booking early."
- **Book a mentor page**: "Pick a mentor and a time below. This page updates live, so a time another team takes disappears. Each team books one session, and can move or cancel it until 24 hours before it starts. All times are Malaysia time (MYT). Booking closes on 25 October 2026." And: "Times are limited and given out first come, first served. The committee is working to have a time for every team, but we can't guarantee it — so we recommend booking as early as you can."
- **Confirming**: the booking bar has an "Also email the details to our team leader" checkbox and a Confirm booking button.
- **Booked**: the session card shows the mentor, the time in MYT and the Zoom link, with "A confirmation email was sent to your team leader", a Cancel session button and "To move it, pick another open time below."
- **Under 24 hours**: "Less than 24 hours to go, so this session can no longer be moved or cancelled. If something has gone wrong, email sdc.xmumhack@gmail.com."
- **Happening now**: the Zoom link becomes a Join the meeting button.
- **Fully booked**: "Every session is booked right now. … The committee may add more — this page updates by itself, so keep it open or check back later." And: "We're sorry. Times are limited and given out first come, first served, so if no more are added we won't be able to arrange a session for every team."
- **Completed**: "Your team met on [date]. Each team gets one session, so there's nothing more to book — good luck with your submission."
