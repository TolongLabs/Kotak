# SDG reasons review

Kotak shows the UN text and a one-line reason for every SDG target chip on the radar and the roadmap, and in the roadmap's What This Path Contributes To card (#391). This page lists the 58 targets beside the UN's official text so a reviewer can check them. 46 are on skill tags and 8 more only on the radar's job chips; the other 4 lost their skill tags in #408's retag. The source of truth is [`data/sdg-reasons.json`](/data/sdg-reasons.json) for the targets and [`occupationSdg.ts`](/apps/web/src/engine/occupationSdg.ts) for the job chips; this page copies both.

## How to review

Claude drafted the reasons. A second Claude model checked the first draft, which led to 14 rewrites. Then two Claude Sonnet 5.5 reviews on 29 October 2026 stood in for a teammate's review, at the maintainer's request (PR #405). The first flagged 13 reasons and gave a new one for 8.8, and all 14 were rewritten. The re-review found no wrong rows in the table but reworded six of them, including 8.8 again. It also found two wrong job rows, groups 13 and 17, which are now split by the jobs each target fits. `meta.reviewers` records both reviews. No person has read the reasons yet, so `meta.quality` stays `auto-generated`.

For each row, check three things:

- The reason is true of the UN text: it names a real way the skill or job helps what the target asks, not some other target.
- It doesn't overclaim. One person's work "helps"; it never "ends", "ensures" or "doubles" anything.
- A user who has never read the SDGs would understand it.

A reason is shown for every skill tagged with its target, so it has to hold for skills of that kind in general. The Skill tags column counts those skills across the 923 jobs. A target with 0 skill tags appears only on job chips, or nowhere: #408's retag left no skill on 1.1, 1.2, 9.4 or 14.2, and no job chip uses them.

To sign off as a person, edit the reasons in `data/sdg-reasons.json` or `occupationSdg.ts`, copy them here, then add your name to `meta.reviewers` and set `meta.quality` to `human-checked`. `bun run build:data` fails if a tagged target or a job chip's target has no row, or if `human-checked` has no reviewer.

## Tags that look wrong

The reviews also flagged tags, which the reasons can't fix. The AI batch set these tags (#77), and #408 checked every one against its target's UN text and retagged the corners whose tags didn't fit. The [SDG retag review](sdg-retag-review.md) lists each flagged tag and what happened to it. The clearest cases:

- **12.8, sustainability information**: Sales and customer advice (Farmers and Ranchers) had nothing about sustainability, so #408 removed the tag. 12.8 now tags Sustainability Strategy (Chief Sustainability Officers), whose campaigns build public awareness.
- **8.8, safe and secure working environments**: skills that protect customers or the public, not workers, lost the tag, such as Web testing and updates (Web Developers), Skin care and hygiene, and Safe route driving. 174 of its 728 tags stayed.
- **9.4, sustainable industry**: none of its 83 tags upgraded infrastructure or industry for efficiency or clean technology, so all went, Celestial measurements (Astronomers) among them.
- **13.2, climate policy**: the forest fire skills now carry 15.1, 11.5 or 4.4.
- **7.2, renewable energy**: Generator Control (Power Plant Operators) lost it.
- **4.4, 8.5, 8.2, 8.8 and 16.6** carried 5,405 of the 6,214 tags. 4.4 and 8.5 fit any job skill, so they stayed, and 4.4 took the place of most removed tags. 8.2, 8.8 and 16.6 kept 295, 174 and 206 of their tags.
